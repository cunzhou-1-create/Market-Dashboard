# 前端与后端API对接计划

## 项目现状分析

### 后端项目
- 使用 FastAPI 框架实现
- 包含完整的 API 模块：auth, market, user, alerts, trade, settings, upload
- 提供了完整的 API 端点，支持认证、市场数据、用户管理等功能
- 配置了 CORS，便于前端调用

### 前端项目
- 使用 React 框架实现
- 包含多个组件：Auth, Header, MainContent, Navigation, Settings, Detail, Task, Trade, AiMarket 等
- 使用上下文管理状态：UserContext, MarketContext, SettingsContext, TaskContext
- 当前使用模拟数据，预留了 API 调用位置
- 缺少 HTTP 客户端库（如 axios）

## 对接计划

### 1. 环境准备
- 为前端项目添加 axios 依赖
- 配置 API 基础 URL

### 2. 创建 API 服务层
- 创建 `src/services/api.js` 文件
- 实现 API 客户端配置，包括基础 URL、请求拦截器（添加认证 token）、响应拦截器（错误处理）
- 封装所有后端 API 端点的调用方法

### 3. 认证模块对接
- 修改 UserContext，使用真实 API 替代模拟数据
- 实现登录、注册、邮箱验证、密码重置等功能
- 实现 token 管理，包括存储、刷新和验证

### 4. 市场数据模块对接
- 修改 MarketContext，使用真实 API 获取市场数据
- 实现市场数据列表获取
- 实现单个币种详情获取
- 实现观察列表管理（添加/移除）
- 实现技术指标获取

### 5. 用户模块对接
- 实现用户资料获取和更新
- 实现头像上传功能
- 实现用户统计信息获取
- 实现登录历史记录获取

### 6. 其他模块对接
- 价格预警模块对接
- 交易模块对接
- 设置模块对接
- 上传模块对接

### 7. 错误处理和用户体验优化
- 实现统一的错误处理机制
- 添加加载状态和错误提示
- 优化认证流程，确保 token 有效性
- 实现自动刷新 token 机制

### 8. 测试和验证
- 测试所有 API 调用是否正常工作
- 验证认证流程是否安全可靠
- 测试边界情况和错误处理
- 确保前端与后端数据结构匹配

## 技术要点

### API 调用模式
- 使用 axios 进行 HTTP 请求
- 实现请求拦截器，自动添加认证 token
- 实现响应拦截器，统一处理错误
- 使用 async/await 处理异步操作

### 状态管理
- 保持现有的上下文管理模式
- 在上下文中实现 API 调用逻辑
- 管理加载状态和错误状态
- 确保数据一致性

### 认证管理
- 使用 localStorage 存储 token
- 实现 token 过期检测和自动刷新
- 处理认证失败的情况
- 确保敏感操作需要认证

### 错误处理
- 实现统一的错误处理函数
- 区分网络错误、认证错误和业务错误
- 提供友好的错误提示
- 确保应用在错误情况下仍能正常运行

## 预期结果

完成对接后，前端将能够：
- 通过真实 API 获取市场数据
- 实现完整的用户认证流程
- 管理用户资料和头像
- 操作观察列表和价格预警
- 执行交易相关操作
- 享受更好的用户体验和数据准确性
